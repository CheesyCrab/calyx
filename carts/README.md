# Calyx Carts

Here are the games, odd little machines, and working examples that ship with
Calyx source. Each runnable cart is an AssemblyScript project built with
[Sunny](../sdk/README.md), packed into one portable `.wasm` file.

Product carts use flat lowercase kebab-case directories. Privileged console UI
lives under `system/`; copyable authoring examples live under `examples/`.
[`hello-sunny`](examples/hello-sunny/README.md) is the maintained in-repository
example used by `tools/new_cart.py`, and [`Sunny API
Lab`](sunny-api-lab/README.md) is the indexed interactive SDK manual.
[Sunny API Lab HD](sunny-api-lab-hd/README.md) demonstrates full color and
compositing outside the curated release catalog. The independent
Node-only first-cart ZIP is maintained under [`../starter/`](../starter/).

First-party carts normally use `GPL-3.0-or-later` as whole works. The
`cart.toml` license covers original code, text, art, audio, generated data, and
compiled Wasm. Third-party material retains its own notice. Independent cart
authors choose their own license; the Calyx runtime license does not determine
a cart license. See [LICENSE.md](../LICENSE.md).

## Start playing—or take one apart

The release player includes four games: [Horizon Burn](horizon-burn/),
[Micro AI War](micro-ai-war/), [Seaway Dig](seaway-dig/), and
[Wormtide](wormtide/). Its Demos shelf holds
[Split-Flap Fortunes](split-flap-fortunes/), [Sunny API Lab](sunny-api-lab/),
and [hello-sunny](examples/hello-sunny/). Roy the cow is filed under Demos;
he has accepted this with professional dignity.

Each cart README explains what it does, how to play, how to build and check
it, where its assets came from, and where its little world stops. Use
[Running Calyx](../docs/RUNNING.md) for prerequisites and keyboard/controller
mappings. The commands below run from the Calyx root—the directory containing
this `carts/` folder.

## Manifest roles

`public_source = true` is repository contribution metadata. It marks a cart as
maintained in the public source tree. `release = true` independently opts the
cart into the curated player catalog. Release and system carts must set
`public_source = true`; maintained examples may remain outside the release
catalog.

The catalog recognizes `role = "boot"`, `role = "launcher"`, and
`role = "hd-boot"` for privileged entry-point carts. Each role is optional and
unique, requires `system = true`, and is hidden from the launcher list. The
Classic boot and launcher appear in every profile. The HD boot sets
`release = false` and appears in Dev and Side B, where it transitions to a
pending HD target. When a Classic boot role exists, presenters run it before
starting a fresh launcher after `sys_exit`.

## Build and run

From the repository root:

```sh
python3 tools/catalog.py build
python3 tools/catalog.py smoke
python3 tools/catalog.py play-window
python3 tools/catalog.py play-sdl
python3 tools/catalog.py play-term
python3 tools/catalog.py serve-pwa --profile release
```

`build` compiles runnable carts, assembles the native developer catalog under
`build/catalog/`, and writes the browser catalog under `web/carts/`. `smoke`
runs the boot-to-launcher flow headlessly, drives one cart change, and writes
PNG and status output under `build/catalog-smoke/`.

Cart compilation uses at most four workers by default while keeping command
output in manifest order. Use `--jobs 1`, `--jobs N`, or
`CALYX_BUILD_JOBS=N` to change the limit. A compile failure prevents catalog
assembly. On a fresh checkout the harness installs local npm dependencies when
needed.

The root wrappers expose the same players:

```sh
./play-window.sh
./play-sdl.sh
./play-term.sh
./serve-pwa.sh --profile release
```

Windows uses the matching `.bat` files.

## Icons

An optional `icon.bin` contains exactly 4096 row-major 64×64 palette indices.
The native catalog copies it, and the browser catalog embeds the same bytes.
Release carts require the icon and its metadata. Keep an `icon-64.png` preview
beside it so the indexed source remains reviewable.

First-party release marks are generated by:

```sh
node tools/build_release_icons.mjs
```

Commit each generated `icon.bin` and matching `icon-64.png` together. Palette
index 0 is transparent.

## Verification

Build one cart with:

```sh
python3 tools/dev.py cart <name>
```

Run the normal repository gate with:

```sh
python3 tools/dev.py commit
```

Conformance wrappers for product and system carts import the maintained cart
source so catalog and oracle builds exercise the same implementation.
